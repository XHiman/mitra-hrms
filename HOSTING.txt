MITRA HRMS - notes for hosting
==============================

What this is: a Python (Flask) web application with a SQLite database. No Node.js, no external
services, no CDN: everything it needs is in this folder.

Requirements
- Python 3.11 or newer (developed and tested on Python 3.13)
- pip install -r requirements.txt   (Flask, waitress, openpyxl)

Full instructions: README.md, section 2 "Production setup". In short:

1. pip install -r requirements.txt
2. Set environment variables:
     HRMS_SECRET_KEY      a long random string (keep it secret, keep it the same across restarts)
     HRMS_SECURE_COOKIES  1   (the site must be served over HTTPS)
     HRMS_INSTANCE_DIR    a private folder outside the web root for the database, uploads and backups
     HRMS_TRUST_PROXY     1   only if it runs behind a reverse proxy (nginx / IIS / load balancer)
3. Data - choose one:
   a) Existing MITRA data: MITRA will send the database file (hrms.db) separately and securely.
      Put it in HRMS_INSTANCE_DIR, then run:   flask --app run init-db   (safe, only upgrades it)
   b) Empty system: flask --app run init-db
                    flask --app run create-admin --username <name> --name "<Full Name>" --emp-code <code>
4. Start:  waitress-serve --listen=127.0.0.1:8080 --call run:create_app
   and put it behind an HTTPS reverse proxy. deploy/PYTHONANYWHERE.md covers PythonAnywhere.
5. Daily jobs (contract reminders) run on the first signed-in request each day; optionally also
   schedule:  flask --app run send-reminders   once a day.
6. Backups: flask --app run backup-db   (schedule daily; copies go to <instance>/backups).

Tests (optional): python -m unittest discover -s tests
(the browser tests need Playwright + Chrome and can be skipped).

The HRMS_INSTANCE_DIR folder holds personal data of MITRA staff. It must not be publicly
reachable and must be backed up.
